# Looks audit 2, Windows look, 2026-10-16

Independent recompute after round 4. A fresh `scripts/render_looks_all.sh` (no failure) reproduced every committed Windows PNG byte for byte, except `windows/edits_states-vs-ref.png` (rendered but never committed) and the Neper `edits_dialog` pair (committed copies stale). Every ref sheet in `ref/windows/` was split into its crops and each crop checked as an exact sub-image of a raw capture in `states/` or `dialogs/` (all sourced except composite open-list sheets), then template-matched against our render at 100 % and diffed with PIL. Every committed state capture was also mapped to the ref sheet crops that contain it: 119 of 200 captured states have a cell, 81 do not (listed per control as captured but not compared).

Definitions as audit 1: structural = ref pixels in a flat fill or a straight run of 11 or more equal pixels whose colour occurs at least 30 times; tolerance 2 levels per channel; text anti-aliasing, ClearType and v3 icon artwork excluded (pixels near any non-flat ink are masked). Status `matched` needs every captured state compared and within tolerance. Result: no control qualifies.

Baked-tile test (own sheets rendered then deleted): the button ring tile fails at 75x32 (top and bottom border missing) and is dotted at 1.5x; the edit chrome (mask, spin, button edit) is correct at widths 90 to 640 and other y but dotted at 1.5x; popup menu and status bar degrade neither at 1.5x nor at other widths.
