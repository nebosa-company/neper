# Looks: one widget set, several platform looks

Decided 2026-10-15 with the maintainer. Progress is tracked in `docs/ui/looks-progress.html`
(generated by `scripts/render_looks.py`; never hand-edited). Screenshots live in
`docs/ui/looks/<look>/<control>.png`.

## Looks

| Look | Profile | State |
|---|---|---|
| Neper | `Neper` | the existing default; every control is the baseline |
| Windows | `Windows` (new) | the MTG Studio v3 look: DevExpress VCL controls on a flat, native-style Windows face. Replaces the working name MtgStudioV3 |
| macOS / iOS | `CupertinoLike` | later; column kept in the matrix, marked planned |
| Android | `MaterialLike` | later; column kept in the matrix, marked planned |

## Mechanism

- A look is a `ThemeTokens` built by `style.reference(palette)` plus a profile-specific builder
  (`style.windows(palette)`), and, where a control's shape differs and not only its colours or
  metrics, a branch on `t.tokens.profile` inside that control. The data grid keeps its own `Look`
  (`e.ui.gridlook`); the Windows grid look is `gridlook.v3()`.
- One widget set. No second control library per platform.
- The Windows look is measured, not invented: the reference is the DevExpress VCL control as
  MTG Studio v3 draws it (mostly `lfFlat` with `NativeStyle`, some `lfOffice11`; no global skin),
  recorded in `docs/grid-parity/` and in `docs/ui/looks/ref/windows/`.

## Screenshots without a display

`e.ui.testing` renders offscreen on the CPU backend and `snapshot` reads the frame back; the PNG is
written with `e.fmt.png`. No window, mouse or keyboard is involved. Each control has a small app
`examples/looks/<control>.e` that draws the control in every state under every look and writes
`docs/ui/looks/<look>/<control>.png`. Reference captures of the real v3 program are taken once,
up front, in a single computer-use pass (`docs/ui/looks/ref/windows/`), so the rest of the work
never needs the screen.

## Control matrix (Delphi / DevExpress -> Neper)

label (TcxLabel), button (TcxButton), checkbox (TcxCheckBox), radio (TcxRadioButton), radio group,
text edit (TcxTextEdit), spin edit, combo box, image combo box, date edit, mask edit, memo, button
edit, token edit, check list box, progress bar, group box, page control (tabs), splitter, status
bar, toolbar button (TdxBarButton), menu bar, popup menu, hint (tooltip), scroll bar, list box,
tree list, vertical grid (property grid), data grid, dialog (form chrome). Gaps with no Neper
control yet (embedded browser, chart, tray icon, native file dialogs) are listed, not built.

## Order of work

1. Core: `Profile.Windows`, `style.windows`, the shared harness, the progress page generator,
   the pilot control (button) end to end.
2. v3 reference captures (one pass).
3. Controls in parallel, one git worktree and branch per group, merged into master in turn.
4. Per control: measure -> implement -> screenshot beside the v3 reference -> mark ready.
   Ready means the Windows PNG matches the reference within tolerance at 100 % and 150 % DPI.
