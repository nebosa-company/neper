# Handover: Neper UI library, Looks and Feels (2026-10-20)

For another account and session that continues the work. Read this file first, then `docs/ui/looks-plan.md`, `docs/ui/looks-howto.md` and the top section of `docs/ui/looks/audit.md`.

## 1. What the project is

One Neper widget set (`lib/e/ui/`, language Neper, files `.e`) with several platform looks, each in Light and Dark, covering the ~30 controls of the Delphi MTG Studio v3 app. Flavors:

| Flavor | Reference used | Look enum |
|---|---|---|
| Windows (the MTG Studio v3 / DevExpress look) | real v3 captures + native Windows 11 gallery | Windows, WindowsDark |
| Linux (GNOME/libadwaita) | GTK4/libadwaita headless captures | Linux, LinuxDark |
| Neper (default) | its own design | Neper, NeperDark |
| macOS / iOS (Cupertino) | none yet | Cupertino, CupertinoDark |
| Android (Material 3) | Material Web in Chrome for Testing (Windows) | Material, MaterialDark |

Progress page (the single source of truth for status): `docs/ui/looks-progress.html`, generated by `python scripts/render_looks.py` from `docs/ui/looks/status.json` plus overlays `docs/ui/looks/status.d/*.json` (merged in sorted filename order, later wins). Never edit old overlays; add a new one with a longer run of `z` so it sorts last.

Status ladder per control x look: planned 0 %, started 20 %, review 60 %, matched 100 %, ready 100 %. `matched` means every captured state reproduces within tolerance (geometry exact, flat pixels within 2 levels, ink boxes within 1 px; ClearType and artwork excluded). `ready` means nothing unverified (not reached so far).

## 3. The key recent finding (read this)

The old v3 references in `docs/ui/looks/ref/windows/` were a double resample: the desktop runs at 150 % DPI, v3 is DPI-unaware, DWM stretches it by 1.5 and `PrintWindow` flag 2 returned that, which was shrunk back. Windows Light grid text could therefore never match. New crisp captures are in `docs/ui/looks/ref/windows-1to1/` (made with `scripts/v3_grab11.ps1`: caption frame from flag 2, client area from flag 0; no system setting changed). Our renders were tuned to the blurred set and are now farther from the crisp one (counted pixels, old then new: data_grid_top 31k to 42k, tree_list_expanded 124k to 129k, vertical_grid 16k to 25k, check_list_box_dialog 22.7k to 24.9k). Constants fitted in rounds 38 and 40 (footer rule shades, edge pixels, `Look.foot_pale`) may be wrong now and must be re-derived from the crisp set. Round 43 retuned the grids to the crisp set (counted px, glyphs included, before to after): data_grid_top left 32.9k to 2.9k, hover 32.6k to 2.5k, group2 26.1k to 17.9k, bottom 41.2k to 19.2k, data_grid_main collection part 35.8k to 19.7k, vertical_grid 23.9k to 5.5k, check_list_box_dialog 30.5k to 13.0k, tree_list_expanded 52.0k to 14.2k. Findings: grid cell text is Segoe UI 11 (pixel-exact against the oracle atlas), header captions and most labels stay Tahoma; crisp captures use plain 1 px rules, a 1 px frame and an inverted-dot focus rectangle; the check list text is ClearType, not greyscale. No row is promoted. Still open: group rows are 1 px high (an 18 px stack broke the layout), the round 38/40 footer constants, check tiles, expander bitmaps and v3 artwork are not re-derived, `data_grid_main` can only be compared on its collection part. The old `NEPER_TEXT_AA=grayscale` oddity is explained: grey marks (`scene.gray_text`) win over the switch.

Caveat: v3 3.235 refuses the maintainer's current collection (schema 3238), so the capture copy uses a fresh schema 366 file via `$env:V3_COLLECTION` (see `v3_states_lib.ps1`). The old `data_grid_main` grouped-by-Rarity layout cannot be reproduced; deck dialogs and some sub menus are not captured (list in the 1to1 README).

## 5. How the work is run (reuse this method)

Orchestrator plus parallel workers, one git worktree each: `D:\Temp\lanes\looksNN-<name>`, branch `looksNN-<name>` cut from master; copy `D:/repos/neper/build/windows/neper-self.exe` into the worktree's `build/windows/`. A worker commits on its branch and does not merge. The orchestrator merges into master (fast-forward when possible), regenerates `docs/ui/looks-progress.html`, commits, then an INDEPENDENT audit agent re-measures with its OWN comparers (workers' scripts have hidden pixels before) and may downgrade. Audits so far: 20 (rounds 41 to 44 unaudited), recorded at the top of `docs/ui/looks/audit.md`. Briefs and method notes: `D:\Temp\claude\briefs\*.md` and `D:\Temp\claude\round20-win.md` / `round20-linux.md` (copy them somewhere durable if that disk is not carried over; the key rules are in section 7).

Compile one sheet app: `build/windows/neper-self.exe emit-executable examples/looks/X.e <repo-root> x64 windows <out>.exe --arena 4g` (retry on arena errors). Render everything: `bash scripts/render_looks_all.sh` (long: do NOT run it in one foreground call, an agent stalled on it; render individual apps and poll). Env switches: `NEPER_LOOKS_SCALE/OUT/ONLY/EXACT/NOTEXT`, `NEPER_TEXT_AA` (grayscale, cleartype, chromewin, androidskia), `NEPER_LOOKS_ANDROID_TEXT`. Scale robustness: `scripts/looks_scale_check.py` at 1.25, 1.5, 2.0.

Merge hazards seen: both sides appending to the end of `lib/e/ui/control.e`; a shared closing `}` falling outside a conflict region; duplicate `use` lines crash the compiler (graph.DuplicateQualifier); PNG conflicts: take theirs then regenerate; never `--theirs` a whole source file; status overlays and JSON: union. Never taskkill a process you did not start. Plain-prose commit messages, no em dashes, trailer `Co-Authored-By: <model> <noreply@anthropic.com>`.

## 6. Reference capture methods (user-approved)

Computer-use control of MTG Studio was denied; use only: PrintWindow of a launched COPY (`D:\Temp\claude\v3run`), posted messages (WM_COMMAND, mouse, focus), and the pointer hook DLL (`scripts/v3_hook/v3hook.c`, built with zig as x86) that fakes GetCursorPos etc. in a process we launch. Native Windows 11 light/dark gallery: `scripts/winnative/gallery.c` + `run.ps1` (refs in `docs/ui/looks/ref/windows-native/`, glyph oracle atlases in `.../glyphs/`). Linux: GTK4/libadwaita headless render in WSL (Xvfb, Cairo) via `scripts/linux/`. Material: `scripts/material/` (gallery.html, capture.mjs, cmp.py, textmask.py, ftprobe.py). Never change system display settings.

## 7. Rules the audits enforce

- Metric: a reference flat pixel counts as off when ours differs by more than 2 levels. Report glyph pixels both excluded (within 2 px of ink) and counted. Shapes, fills, shadows, state layers and 2 px outline rings are always compared. Stamped marks and large baked regions do not count; small baked icon tiles may.
- Draw rules, do not stamp captured pixel regions. Constants fitted per capture are flagged.
- Spec-written CSS references (no Material Web component) cap at review.
- Do not claim `matched` from your own comparer alone; the next audit decides.
- Windows, Linux, Neper, Cupertino, Material PNGs that a change should not touch must re-render byte-identical (sample 6 to 10 sheets each time).

## 8. Known quirks

- Neper language traps: no locals named `target/text/width/str/mem/button/...`, typed float literals, no `ret` of a tuple call, `\\` in strings, heredoc backslashes mangle JSON (use forward slashes).
- Hinted text: GDI Tahoma advance tables, `lib/e/gfx/cleartype.e` (96 % of oracle glyphs pixel-exact; 7 atlases below 95 %: Segoe UI 24, Tahoma 21/13/16, Tahoma Bold 14/21), Android text model `lib/e/gfx/dwtext.e` (principled, ~93-96 % ink exact against Chrome-on-Windows).
- `git stash@{0}` in the neper repo holds 419 files of formatter churn that is not ours; leave it.
- Stop wait loops left behind by workers (`until ... sleep` polling stale files) when check-ins mention them.
