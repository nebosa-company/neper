Why Neper is built for the agent loop

October 21, 2026 · design notes

A model editing code does not browse it the way you do. It sees a window of text, guesses what lies outside it, and pays for every token it reads and writes. Neper's design goal is that a model should not be able to write a line whose meaning depends on context it cannot see. This post lists the rules, commands and diagnostics that follow from that, what each one is for, and which of the claims we have not proved yet.

How agents fail on code

The rules below came from failures in measured agent transcripts, not from taste.

FailureWhat the model doesWhat it costs
Hidden contextEdits a function without seeing the overload, macro, implicit cast or lifetime that changes its meaningA plausible, wrong edit
Ambiguous searchA text search for a definition returns several hits or noneWhole-file reads; context in the hundreds of thousands of tokens
Hallucinated APICalls a function that does not exist or is only plannedRepair turns
Unreadable diagnosticMisreads a message that names no subjectThree or more turns instead of one or two
Brittle editApplies a text or line edit to a file that has changedPartial application

Language rules that make a search reliable

Section 14 of the spec lists invariants that are rules, not style advice. They exist so that a search, a glob or an anchored edit is reliable rather than probabilistic.

  • One definition per name, no overloading. Searching for ^fn dot returns exactly one line in the module that defines it.
  • Declarations start at column 0, and the file path is the module name. Searching for ^fn lists functions. A glob finds a module without opening it. An unclosed bracket cannot cross a declaration keyword, so a dropped ) is reported where it opened, not 200 lines later.
  • Every cross-module reference is qualified (mem.alloc), so the definition is one search away.
  • No macros, no preprocessor, no implicit conversions. What you read is what compiles, and every cast is written down and greppable.
  • One canonical layout, checked by neper fmt --check, so diffs are minimal and edits land where you expect. Casing is enforced too: a name's kind is visible without a lookup.
  • Order-independent module scope. An insertion can go anywhere, with no forward declarations to keep in sync.

Beyond that list, errors are values handled at the statement (try, -> err, ret ok), and a local may not shadow a reserved word, a module-scope function, a use qualifier or a builtin. That last rule looks fussy. It is the reason a name means one thing within a file, and it was a leading cause of failed builds in our transcripts. The compiler reports it as E-NAME-0003 with a machine-applicable rename. The grammar itself is closed: 94 token kinds and 54 syntax-node kinds.

Tokens are measured, not guessed

A lexical token is not a model token. Across our corpus there are about 1.27 model tokens per lexical token, and the language card publishes the cost per terminal for two tokenizers.

So the card says to prefer usize where the width is free. The policy is that a spelling change must show a measured token or repair-turn improvement; a character-count argument is not accepted. The biggest lever we found is not syntax at all. A turn that reads whole files carries 400–500 K tokens of context, against 1–5 K when the model asks context-file for the same function.

The compiler as an API

Every command emits versioned JSONL, and every semantic answer is bound to a snapshot of the program so a stale answer is detectable. All of the following are implemented and exercised by both self-host suites.

CommandWhat it answers
index, uses-fileEvery definition and resolved reference, with byte-precise spans
context-fileOne function's signature and its contract: allocation, borrow, mutation, errors, threads. Pages with --budget, --bytes, --cursor
plan-rename-file, plan-add-parameter-file, plan-change-signature-file, plan-replace-expression-fileA typed edit the compiler computed, with file-hash preconditions and a re-check postcondition
apply-planApplies a plan to every file or to none
test-impact-file, test-file --onlyOnly the tests an edit reaches
query-batchMany queries over one check, with --deadline and an instance budget

The card prescribes the loop: locate with index or uses-file, read context-file for what the change touches, make a plan, apply-plan, then check-file, fmt --check, test-impact-file and test-file --only. A stale file hash aborts the plan instead of half-applying it, so a concurrent edit cannot leave a half-migrated codebase.

Diagnostics written for the reader that repairs

Codes look like E-TYPE-0002. The code, not the message, is what a tool keys on. At the card's last render all 15 families (E-SAFETY alone has 25 codes) are pinned by conformance goldens or the suites, and each family has a 9999 catch-all so a gap is visible. A diagnostic carries its expected and actual types, related sites and fixes. We measured the effect of the identity: a repair prompt that carries the code, span and expected-versus-found takes a median of one to two turns, and three or more without it. The card also embeds reject fixtures for the common traps, so the model sees the failure before it causes it.

A card that cannot drift

The language card is rendered by script from the grammar revision and stamped with a content hash. A card whose hash is not the render of its grammar is stale. Command and diagnostic standing is read from the compiler and the suites when the card is rendered, so the model is never told a command exists because someone wrote it down. The repository's agent instructions encode the measured habits: name the queue item and acceptance list in every build prompt (bare “continue” prompts correlate with 59–72% repeat rates), read the card first, resolve symbols before opening files, and keep verify-only turns separate from build turns.

What we have not proved

Compiler-enforced ownership and lifetime, the one-query enumeration of every unsafe site, and declaration-level incremental reuse with latency budgets are adopted requirements with delivery tracks, not shipped claims. The comparison against other languages is a hypothesis until a held-out evaluation on two model families passes; until then we do not publish “faster” or “safer” for LLMs. A checked contract is not business correctness, and a clean build from the C bootstrap is not proof, because the bootstrap is more permissive than the self-hosted compiler.
