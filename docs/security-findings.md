# Neper Security Findings

Read-only application-security audit of the Neper compiler, runtime, standard
library, and build tooling. Generated by fanning the review out across 12
area-specialized subagents (deepseek-v4-pro) with evidence-first reporting; the
highest-severity items were independently re-verified against source.

## Remediation status (applied)

The high and medium findings and most of the low tail were fixed. Verification:
`scripts/build-bootstrap.ps1` and `scripts/build-selfhost.ps1` both exit 0 (the C
bootstrap and the self-hosted compiler, which compiles every `src/*.e` and
`lib/e/*.e`), and 17 targeted fixtures pass: `crypto_secret`, `algo_privacy`,
`misc_gaps` (PKCE), `crypto_cipher`, `crypto_aead`, `crypto_x509`, `crypto_kx`,
`crypto_pq`, `net_tls`, `net_dns`, `asset`, `fmt_msgpack`, `fmt_cbor`, `fmt_tar`,
`fmt_zip`, `fmt_yaml`, `fmt_xml` (plus `asset_invalid`, which correctly rejects a
bad manifest).

| Finding | Fix |
|---|---|
| high — `check.e` `array_length + 1` | reject `usize::MAX` array length in `resource_init_fields` |
| high — `assets.e` `path:` traversal | `asset_path_safe` rejects absolute/`..`/`:` paths at manifest parse |
| med — `cipher.e` padding oracle | `unpad_pkcs7` folds all bytes into a mask (no early exit) |
| med — `tls.e` empty `server_name` | `verify_certificate_set` returns `InvalidCertificate` |
| med — `apply-plan` traversal | `plan_path_safe` rejects absolute/`..`/`:` plan paths |
| med — `msgpack.e`/`cbor.e` unbounded alloc | 16 MiB cap / `count > remaining` bound |
| med — `bonsai_driver.py` PROTECTED bypass | `read_lines`/`search` route through `_inside` |
| med — `bonsai_driver.py` shell RCE | split into a separate `--allow-shell` flag |
| med — Shamir/PKCE/DP weak PRNG | `os.random` defaults + deterministic `_seeded` test variants |
| med — parser/`graph.e` recursion | `enter()`/depth guards on all unguarded sites |
| med — `neper.c` recursion | `nesting_enter`/`leave` on parse/`check_expr`/`type_layout` |
| low — `pointer_leaf_count`, `binary.e`, `emit_x64.e`, `regalloc.e`, `lower.e`, `nir.e`, `lex.e`, `tar.e`, `zip.e`, `yaml.e`, `xml.e`, `dns.e`, `O_CLOEXEC`, script quoting | overflow guards / bounds / surrogate rejection / quoting |

### Deferred (documented, not yet fixed)

- **low** `project.e` symlink containment — needs `realpath`/`openat2` containment;
  larger change than a one-line guard.
- **low** `save_bytes` `.tmp` symlink — `os.create_new` (O_EXCL) would regress
  crash recovery on a leftover `.tmp`; needs unlink-then-create handling.
- **low** `secret.e` zeroization — intermediate share/term buffers not wiped.
- **info** `em_link.e` xxHash64 folding — a hash-recompute check was added, but the
  fold key is still non-cryptographic (theoretical; adversary already controls code).
- **info/notes** `append_type_instance_key` and `debug_type_name` recursion in
  `neper.c` remain unguarded (secondary sites; the primary parser/checker paths are).
- **info** cosmetic UTF-8/overwrite/doc items (`main.e` lone surrogates, capture-file
  truncate semantics, `html/template` URI scheme, `text/template` escaping, PATH-based
  tool lookup) — accepted or documentation-only.

## Scope & method

- **Root:** `D:\repos\neper` (self-hosted `.e` compiler, `src/`; C99 bootstrap
  `bootstrap/`; stdlib `lib/e/`; automation `scripts/`, `benchmarks/`, `tests/`).
- **Tracks (12):** bootstrap C · compiler front-end · semantic/check · IR/lower ·
  backend/codegen · linker/object/project · CLI/tooling/runtime · crypto ·
  network/OS · formats/text · scripts/build · secrets/credential hygiene.
- **Method:** each track grep-patterns its files, then reads the surrounding
  region to confirm exact line numbers. Findings without a confirmed `file:line`
  were omitted or marked "needs verification". Severity is calibrated
  (`critical/high/medium/low/info`); `high`/`critical` are reserved for genuinely
  exploitable memory-safety, injection, or cryptographic failures.
- **Verified ✓** means the parent re-read the cited source and confirmed the code.

## Executive summary

| Severity | Count |
|---|---|
| critical | 0 |
| high | 2 |
| medium | 17 |
| low | 29 |
| info | 14 |
| **total** | **62** |

The two **high** findings are:

1. an unguarded `array_length + 1` in the semantic checker's resource tracking
   (`src/check.e:15213`) that overflows to a zero-sized allocation and then writes
   out of bounds (compiler DoS with a memory-corruption possibility), reached by an
   oversized array type the checker otherwise accepts; and
2. an embedded-asset `path:` value joined under the project root without `..`/
   absolute/symlink rejection (`src/assets.e:506`, `320-341`) that exfiltrates
   arbitrary readable files into the built binary when an untrusted `project.yaml`
   is built.

The medium findings cluster into a few recurring themes: unbounded recursion /
stack-exhaustion DoS on untrusted source (`neper.c`, `parse.e`, `graph.e`); a
`apply-plan` arbitrary-file-write via plan-supplied paths (`main.e:4810`); weak or
non-cryptographic randomness in crypto/Shamir/PKCE (`secret.e`, `random.e`,
`http/auth.e`); side-channel and padding-oracle primitives (`bignum.e`, `cipher.e`,
`kx.e`); TLS hostname verification silently skipped for empty `server_name`
(`tls.e:641`); unbounded-allocation DoS in msgpack/cbor; and two script command-
injection paths (`bonsai_driver.py`). The low/info tail is dominated by
integer-overflow hardening gaps that are mostly latent (not reachable through
in-tree callers) plus UTF-8/parsing robustness items.

No secrets or credentials were found in the working tree or git history.

## 1. Bootstrap C compiler (`bootstrap/neper.c`, `bootstrap/runtime.c`)

### [medium] Out-of-bounds stack read in `parse_integer_value` ✓
- **Location:** `bootstrap/neper.c:1343` (and 1347–1348)
- **Category:** out-of-bounds read
- **Description:** `parse_integer_value` copies an integer literal into
  `char text[128]` via `copy_text` (line 1340), which truncates to 127 bytes, but
  keeps the untruncated `size_t length = (size_t)token->length` (line 1336). Line
  1343 computes `text + length - candidate`, and the digits loop (1347–1348) reads
  `text[i]` for `i < length - suffix_length`. For any integer literal longer than
  127 bytes, both read past the 128-byte stack buffer. The digits loop's guard
  limits only `n` (the output count), not `i`, so a long literal with `_`
  separators reads `text[i]` far out of bounds.
- **Exploitability:** trivial — a 128+-byte digit run in a `.e` source file.
  Read-only primitive (bytes are only compared/copied into a bounded `digits`
  buffer), so impact is UB / possible SIGSEGV and incorrect parsing, not a direct
  write or disclosure primitive.
- **Recommendation:** clamp `length` to the copied size after `copy_text`
  (`length = length < sizeof(text)-1 ? length : sizeof(text)-1`), or index `text`
  using the bounded length.

### [medium] Unbounded recursion on deeply nested input → compiler stack overflow (DoS)
- **Location:** `bootstrap/neper.c:1227` (and 1534, 1696, 2044, 2576, 3261, 3774, 6576)
- **Category:** denial of service (stack exhaustion)
- **Description:** the recursive-descent front end has no nesting-depth limit for
  types, expressions, or blocks. `parse_type` self-recurses on `*`/`[]`;
  `parse_primary`/`parse_unary` re-enter `parse_expression`; `parse_block` ↔
  `parse_statement` recurse per nested construct; `check_expr`/`type_layout`/
  `append_type_instance_key`/`debug_type_name` recurse per type/expr depth.
  `MAX_TOKENS` is 262144, so ~100k levels of nesting is expressible, each with a
  large `Type` frame.
- **Exploitability:** reliable DoS — a file like `fn f() { let x = ` followed by
  tens of thousands of `*`/`(`/`!`/`{` recurses until stack overflow. No code
  execution demonstrated.
- **Recommendation:** thread an explicit nesting counter (e.g. `MAX_NESTING ~ 1024`)
  through the parser/checker/emitter recursion and emit a diagnostic instead,
  mirroring the existing `MAX_LOOP_DEPTH` guard (`neper.c:4187`).

### [low] Token length stored in a 32-bit `int` wraps negative for very large tokens
- **Location:** `bootstrap/neper.c:719`
- **Category:** integer truncation / signed-unsigned confusion
- **Description:** `token->length = (int)(end - start)` wraps negative for a token
  over `INT_MAX` bytes; downstream casts it back to `size_t` (e.g. `neper.c:1336`,
  692, 616), turning a negative length into a huge `size_t` and driving wild reads.
- **Exploitability:** requires a single >2 GiB lexeme (impractical but not
  impossible on 64-bit). Amplifies the `parse_integer_value` issue.
- **Recommendation:** store token length as `size_t` or clamp at lex time.

### [info] `quote_arg`/`quote_wide_arg` do not escape backslashes (Windows quoting)
- **Location:** `bootstrap/neper.c:7574` (and 7609)
- **Category:** command-line quoting
- **Description:** wraps args in quotes but backslash-escapes only `"`, so a run of
  backslashes before a closing/embedded quote is misparsed by cmd.exe/ml64/link.
  The values come from the invoking user's own argv paths, not `.e` source.
- **Exploitability:** confined to a user compiling from a path they chose; info/low.
- **Recommendation:** implement correct Windows quoting (double backslashes before
  each `"`), as already done in `runtime.c:514-535`, or use `CreateProcess` with
  explicit argv instead of a generated batch file.

### [info] `readdir` capacity doubling can overflow `size_t`
- **Location:** `bootstrap/runtime.c:494` (and 861)
- **Category:** integer overflow
- **Description:** `capacity *= 2` then `np_arena_alloc(arena, capacity * sizeof(NpDirEntry), 8)`
  wraps to 0 at `capacity == 2^60`, after which a non-null zero-size allocation is
  followed by an out-of-bounds `np_copy`.
- **Exploitability:** theoretically requires ~2^59 directory entries; not practical.
- **Recommendation:** guard the doubling (`if (capacity > SIZE_MAX/2) goto oom`).

## 2. Compiler front-end (`src/lex.e`, `parse.e`, `syntax.e`, `source.e`, `error_table.e`)

### [medium] Unbounded recursion in type parsing bypasses the 128-level depth guard ✓
- **Location:** `src/parse.e:961` (also 982, 1002)
- **Category:** denial of service (stack exhaustion)
- **Description:** `parse_type_node` recurses into itself for every pointer (`*`),
  slice (`[]`), and array (`[N]`) without calling `enter()`, the depth guard at
  `parse.e:131-139` that caps `p.depth` at 128. The same unbounded path runs
  through nested generic arguments and function types. `fn f(x: ****...u8)`
  allocates one native frame per `*`.
- **Exploitability:** trivial — tens of thousands of `*`/`[]` in a type position
  overflow the stack and crash the compiler on untrusted input.
- **Recommendation:** apply `enter()`/depth accounting inside `parse_type_node`
  (or a wrapper) so pointer/slice/array/generic/function-type nesting is capped.

### [medium] `else if` chains recurse without the depth guard
- **Location:** `src/parse.e:1287`
- **Category:** denial of service (stack exhaustion)
- **Description:** `parse_if_statement` calls `try parse_if_statement(p)` directly
  for each `else if`; the depth budget consumed by the level's condition/body is
  restored before the recursive call, so `p.depth` never rises to the 128 cap.
- **Exploitability:** trivial — `if a {} else if a {} ...` repeated ~10k times
  overflows the stack.
- **Recommendation:** add `enter()` accounting to each `else if` recursion or
  refactor into an iterative loop.

### [medium] Dereference-place chains recurse without the depth guard
- **Location:** `src/parse.e:1202`
- **Category:** denial of service (stack exhaustion)
- **Description:** `parse_place_node` recurses into itself for each leading `*`
  with no `enter()` call (`* * * ... x = 0`).
- **Exploitability:** trivial stack-overflow DoS.
- **Recommendation:** add `enter()` accounting or route through the already-guarded
  `parse_prefix_node`.

### [low] `column_from` / `column_utf16_at` index `source[at]` without clamping
- **Location:** `src/lex.e:222` (and 271)
- **Category:** missing bounds check (defense-in-depth)
- **Description:** both loop `while at < offset { ... source[at] ... }` without the
  `at < source.len` bound that sibling `line_of` applies (`lex.e:186`). All current
  callers guard before calling, so this is a latent invariant, not a reachable
  overflow today.
- **Recommendation:** add `at < source.len` to both loop conditions (mirror
  `line_of`).

**Notes (front-end):** UTF-8 validation correctly rejects overlongs/surrogates/
out-of-range scalars; unterminated strings/raw strings/comments terminate at
newline/EOF without over-reading; parser node/child arrays are bounds-checked
against caller-sized pools.

## 3. Semantic checking (`src/check.e`, `resolve.e`, `graph.e`)

### [high] `array_length + 1` overflows to zero → out-of-bounds arena write ✓
- **Location:** `src/check.e:15213` (and 15215, 15217-15222)
- **Category:** integer overflow / out-of-bounds write
- **Description:** `resource_init_fields` allocates
  `mem.alloc[u8](c.arena, local_type.array_length + 1usize)` and
  `mem.alloc[usize](c.arena, local_type.array_length + 1usize)`. `array_length` is
  attacker-controlled and can be `usize::MAX` — `array_length_value`
  (`check.e:1772-1778`) imposes no upper bound and `integer_representable`
  (`check.e:5262-5267`) accepts any non-negative magnitude for `usize`/`u64`.
  When `array_length == usize::MAX`, `+ 1usize` wraps to 0, the allocator returns a
  non-null zero-length slice (`bootstrap/runtime.c:179-181`), and the loop
  `while element_at < local_type.array_length` writes `2^64-1` entries into
  `elements`/`acquired` past the allocation.
- **Exploitability:** reachable from a single source file declaring
  `var a: [18446744073709551615]File`. Primary effect is a deterministic compiler
  crash (DoS); the write also corrupts live arena memory before faulting, so
  memory corruption is a secondary possibility.
- **Recommendation:** bound array lengths at type-formation time (reject any array
  whose `length * element_size` — and `length + 1` — overflows or exceeds a sane
  cap), and guard `resource_init_fields` specifically before the `+1`.

### [medium] Module-graph dependency DFS recurses with no depth limit ✓
- **Location:** `src/graph.e:884`
- **Category:** denial of service (stack exhaustion)
- **Description:** `graph.visit` recurses `visit(g, target_module)` directly; only
  cycles are detected (`visit_state == 1`), so a long acyclic import chain recurses
  one native frame per module with no depth counter.
- **Exploitability:** a crafted project with ~10k+ linearly chained modules
  overflows the native stack (deterministic DoS, not memory corruption).
- **Recommendation:** convert to an iterative worklist/post-order traversal, or add
  a depth guard reporting "dependency chain too deep".

### [medium] No overflow check on array length before it is multiplied by element size
- **Location:** `src/check.e:1776`
- **Category:** validation gap / integer overflow
- **Description:** `array_length_value` checks only `!value.negative` and the
  `usize` type; it imposes no upper bound and never checks that
  `length * element_size` fits `usize`. Oversized arrays pass malformed state to
  layout/codegen (e.g. `[18446744073709551615]i64`), where `length * 8` wraps to an
  undersized allocation/frame.
- **Recommendation:** add a single choke point validating `array_length` and
  `array_length * scalar_size(element)` (with overflow checks); reject otherwise.

### [low] `pointer_leaf_count` multiplies array lengths without overflow check
- **Location:** `src/check.e:12237`
- **Category:** integer overflow (borrow-check arithmetic)
- **Description:** `elements * ty.array_length` can overflow `usize` for nested
  oversized arrays; the result feeds borrow/move decisions, so a wrap can yield an
  incorrect borrow-check result (soundness defect, not compiler memory corruption).
- **Recommendation:** use saturating/checked multiplication or bound array lengths.

**Notes (semantic):** const-folding arithmetic has correct overflow guards;
integer-literal parsing checks `value > (max - digit)/base`; the comptime
interpreter is bounded by a 10M-step budget plus a 64-deep call limit; shift
counts are bounded; format-verb arrays are bounds-checked.

## 4. IR lowering & layout (`src/lower.e`, `nir.e`, `layout.e`)

### [low] Unchecked `info.size + 7` overflow in stack-slot sizing
- **Location:** `src/lower.e:96` (also 159, 649, 2041, 2527, 2722, 2904, 3294, 3413, 4088, 5561)
- **Category:** integer overflow
- **Description:** `slots = (info.size + 7usize) / 8usize`; `info.size` may be near
  `usize::MAX`, so `+7` wraps, `slots` becomes 0 → forced to 1, while a `Copy` is
  emitted with `immediate = info.size` (up to 2^64-1) → undersized slot, huge copy.
- **Exploitability:** pathological (~2^64) type sizes; "needs verification".
- **Recommendation:** use `layout.align_up(info.size, 8) / 8` (which is
  overflow-checked) or reject oversized frame/type sizes before lowering.

### [low] Unchecked offset/size accumulation in global data-area layout
- **Location:** `src/nir.e:562` (and 564, 575)
- **Category:** integer overflow
- **Description:** `global_area_offset` does plain `offset = offset + alignment - remainder`
  and `offset = offset + item.size` with no overflow test; near-2^64 sizes wrap to
  a too-small data area and wrong per-global offsets.
- **Recommendation:** reuse `layout.align_up`/checked addition (as `call_return_layout`
  already does at `lower.e:770-773`).

### [low] Unchecked align-up/size accumulation in GPU shared-memory layout
- **Location:** `src/lower.e:6489` (and 6490)
- **Category:** integer overflow
- **Description:** `(total + alignment - 1usize) / alignment * alignment` and
  `total = offset + info.size` are unguarded; wrap mis-lays-out kernel shared memory.
- **Recommendation:** replace with `layout.align_up` and the `offset > MAX - info.size`
  guard used elsewhere.

### [info] Layout recomputed without memoization (quadratic on nested `@reorder` structs)
- **Location:** `src/layout.e:60`
- **Category:** denial of service (compile time)
- **Description:** `reordered_struct` scans fields twice per class and re-enters
  `type_info_depth`; lowering re-runs it per use site. Depth is bounded
  (`depth > c.aggregate_count`), so polynomial, but a pathological source inflates
  compile time.
- **Recommendation:** memoize per-aggregate `type_info` results.

**Notes (IR/lower):** instruction/block/operand/function/global buffers are all
written through capacity-checked entry points returning `Capacity` rather than
overrunning; `src/layout.e`'s `align_up`/multiply/add are overflow-checked.

## 5. Backend: codegen & emit (`codegen_x64.e`, `emit_x64.e`, `regalloc.e`, `disasm_x64.e`, `binary.e`)

### [low] `binary.e` bounds checks use `offset + N`, which wraps for huge offsets
- **Location:** `src/binary.e:130` (also 142, 154, 163, 168, 173)
- **Category:** integer overflow (bounds-check bypass)
- **Description:** `patch_little_u32`/`read_u16`/`read_u32`/`read_u64` etc. validate
  with `offset + N > buffer.count`, which wraps for `offset` near `usize::MAX`,
  bypassing the guard and indexing far out of bounds.
- **Exploitability:** latent — current callers (em.e) validate `offset <= len` first.
- **Recommendation:** use subtraction form `if offset > buffer.count - N`.

### [low] `patch_relative32` silently wraps out-of-range rel32 displacements
- **Location:** `src/emit_x64.e:986`
- **Category:** relocation / overflow
- **Description:** forward `destination - following` and backward
  `4294967296usize - magnitude` are neither range-checked; |distance| ≥ 2^32 wraps
  and is truncated to 32 bits, silently corrupting jump/call targets.
- **Exploitability:** only when an image spans >2 GB (the rel32 architectural limit);
  not memory-unsafe.
- **Recommendation:** reject |distance| > 0x7FFFFFFF with a clear error.

### [low] `stack_displacement`/`frame_size` overflow for very large slot counts
- **Location:** `src/emit_x64.e:606` (and 561)
- **Category:** integer overflow
- **Description:** `(slot + 1usize) * 8usize` and `stack_slots * 8usize` are
  unguarded; huge slot counts wrap into wrong stack displacements.
- **Exploitability:** latent (slot counts are bounded by NIR counts in-tree).
- **Recommendation:** clamp or error before emitting displacements.

### [low] `patch_relative8` writes `buffer.bytes[displacement_at]` with no bounds check
- **Location:** `src/emit_x64.e:557`
- **Category:** out-of-bounds write (latent)
- **Description:** validates the jump distance but not `displacement_at < buffer.count`,
  unlike every other patch routine.
- **Exploitability:** current callers pass `buffer.count` at emission time; latent.
- **Recommendation:** add the bounds check, matching the other patch functions.

### [low] `regalloc.allocate` computes heap size with a wrapping multiplication
- **Location:** `src/regalloc.e:663`
- **Category:** integer overflow
- **Description:** `register_count * capacity * 2usize + 1usize` can overflow for
  `capacity` near 2^59, under-sizing the arena.
- **Exploitability:** latent (value counts bounded by real allocations).
- **Recommendation:** guard the multiplication with checked arithmetic.

### [info] `regalloc` permits 16 registers but codegen maps only indices 0..9
- **Location:** `src/regalloc.e:656`
- **Category:** contract inconsistency
- **Description:** the allocator accepts `register_count` up to 16, but
  `hardware_register` (`codegen_x64.e:199-211`) returns `Unsupported` for indices
  ≥ 10; the production caller uses 10.
- **Recommendation:** tighten the allocator cap to `register_pool_count()`.

**Notes (backend):** all machine-code emission goes through checked writers that
return `Capacity`/`InvalidByte` rather than overflowing; the disassembler is a
fully bounds-checked linear sweep; immediate/shift/condition paths reject
out-of-range values. No critical/high findings.

## 6. Linker, object formats & project resolution (`em.e`, `em_link.e`, `link_elf.e`, `link_pe.e`, `object_*.e`, `artifact_hash.e`, `assets.e`, `project.e`, `lookup.e`)

### [high] Embedded-asset `path:` value allows path traversal out of the project root ✓
- **Location:** `src/assets.e:506` (and `320-341` `asset_join`, `292-296` `parse_manifest`)
- **Category:** path traversal / arbitrary file read (build-time exfiltration)
- **Description:** `asset_load` resolves each declared asset via
  `asset_join(a, root, entries[i].path)` then `source.load(a, path)` with no
  validation of the manifest `path:` value. `asset_join` is a plain
  `root + "/" + leaf` concatenation; `parse_manifest` stores the `path` scalar
  verbatim. A `path:` of `../../../../Users/x/.ssh/id_rsa` (or `..\..\..` on
  Windows) is joined to the project root and read, so `source.load` escapes the
  root. Symlinks are likewise followed (no realpath containment). The bytes are
  embedded into the generated `lib/e/asset.e` overlay via `asset_literal`, so a
  malicious `project.yaml` exfiltrates arbitrary files the build user can read into
  the produced binary/manifest.
- **Exploitability:** build-time arbitrary-file read/exfiltration in a supply-chain
  scenario (building an untrusted third-party project). No code execution.
- **Recommendation:** reject absolute paths, `..` segments, and (Windows) drive/UNC
  prefixes; canonicalize the joined path and require it to remain under `root`;
  refuse or re-check symlinks before `source.load`.

### [low] Module source selection follows symlinks without containment (readdir→open TOCTOU)
- **Location:** `src/project.e:386`
- **Category:** symlink escape / TOCTOU
- **Description:** `select_source` accepts `entry.kind == .Symlink` as a source
  candidate, then opens it without a realpath/containment check, and there is a
  TOCTOU between the cached `os.readdir` listing and the later open.
- **Exploitability:** low — the attacker already controls files/symlinks in the
  tree; extends a partial write to arbitrary readable files.
- **Recommendation:** resolve symlink targets and require they stay under the root;
  re-stat at open time or open relative to a directory handle.

### [low] Function dedup/folding keys on non-cryptographic xxHash64
- **Location:** `src/em_link.e:903-913` (verify `289-292`; hash `artifact_hash.e:32-34`)
- **Category:** hash collision → silent miscompilation
- **Description:** the linker folds identical functions by `content_hash` (xxHash64);
  on a hit the later function's offset is redirected to the earlier copy and its
  code dropped. `verify` only re-checks each function's stored hash against its own
  bytes — it never compares the two folded functions' bytes — so a genuine collision
  folds distinct code with no detection.
- **Recommendation:** compare the two functions' code/relocation bytes before
  folding (or use a cryptographic digest for the fold key).

### [info] `link-em`/`validate-em`/`manifest-em` accept `.em` artifacts authenticated only by CRC-32C
- **Location:** `src/main.e:5496-5506` (`load_artifact`); called at `10143`, `2439`, `10088`
- **Category:** integrity vs authenticity (defense-in-depth)
- **Description:** these CLI paths load user-supplied `.em` files with only
  `em.validate` (CRC-32C + layout checks) and then emit their machine code into the
  output executable. CRC-32C is trivially forgeable and carries no authenticity.
  The incremental build path is safe (it additionally requires SHA-256 against the
  HMAC-authenticated manifest, `main.e:6419-6426`), but the direct link paths do not.
- **Recommendation:** document that `.em` artifacts are code containers; extend
  HMAC/SHA-256 verification to the direct link path or warn when an artifact has no
  authenticated digest.

**Notes (linker):** the `.em` binary readers (`em.e` string_bounds/read_code_functions/
check_layout/validate, and `find_section_unchecked`) are consistently bounds-checked
(offset/length guarded, counts u32 vs offsets u64 so multiply-add cannot overflow);
cache-auth reuse is correctly gated on HMAC'd manifest + SHA-256 and unauthenticated
manifests reuse nothing; `cache_auth_verify` uses constant-time tag comparison. An
earlier-pass "module name may contain `/`/`\`/`:`" item was investigated and
discarded: import names are lexer Identifier tokens joined by `.`, and `module_parts`
rejects empty dot-segments, so those bytes cannot appear in a module name and `..`
traversal is not reachable that way. Asset codegen escapes `"`/`\`/non-printables
(`asset_literal`), so no source injection via asset names/bytes.

## 7. CLI, tooling & runtime (`main.e`, `tool.e`, `stats.e`, `decimal.e`, `runtime_*.e`)

### [medium] `apply-plan` joins plan-supplied paths under `--root` without containment → arbitrary file write ✓
- **Location:** `src/main.e:4810-4821` (`plan_source_path`); write at `src/main.e:4758` via `save_bytes`
- **Category:** path traversal / arbitrary file write
- **Description:** `plan_source_path` takes `path` straight from the plan JSON
  (`json_str_after(line, "\"path\":\"")`) and joins it with the `--root`/`--project-src`
  directory (`nptest_append(joined, n, path)`, line 4820) with no `..`/absolute/
  drive-letter sanitization. The result is stored in `file_paths[]` (`main.e:4686`)
  and later written by `save_bytes` (`main.e:4758`). A crafted plan whose `"path"` is
  `../victim` escapes the root. The precondition SHA-256 (`main.e:4683-4685`) is not a
  real barrier — the plan author controls the recorded hash and can compute the
  target's hash.
- **Exploitability:** overwrite of arbitrary files the user can write, with
  attacker-chosen content, when an untrusted plan file is applied.
- **Recommendation:** reject `path` values containing `..`, leading `/` or a drive
  letter, and resolve/verify containment under `root` before writing.

### [low] Predictable `<path>.tmp` staging name follows symlinks (TOCTOU)
- **Location:** `src/main.e:5157-5161` (`save_bytes`), `5164-5172` (`write_file`)
- **Category:** temp-file / symlink
- **Description:** `save_bytes` writes to a fixed sibling `<path>.tmp`
  (`with_suffix(a, path, ".tmp")`) opened with `create: true, truncate: true`.
  `os.open` follows symlinks, so a pre-planted symlink at `<path>.tmp` redirects the
  write to an arbitrary file, and `os.replace(staged, path, true, false)` renames the
  symlink onto `path`. Requires write access to the output directory.
- **Recommendation:** create the staging file with `O_EXCL`/no-follow semantics, or
  unlink any pre-existing `.tmp` first.

### [low] Linux `neper_os_open` omits `O_CLOEXEC`; descriptors leak into spawned children
- **Location:** `src/runtime_elf_x64.s:873-904` (flag assembly); fork/exec at `1707-1745`
- **Category:** fd leak / process hygiene
- **Description:** the openat flags are only `O_WRONLY/O_RDWR|O_CREAT|O_TRUNC|O_APPEND`;
  `O_CLOEXEC` (0x80000) is never set, and `neper_os_spawn` uses `fork`+`execve` rather
  than `posix_spawn`, so every descriptor opened via `os.open` is inherited by the
  child. `lib/e/os.linux.e:65,73` deliberately sets `O_CLOEXEC` — inconsistency.
- **Recommendation:** OR `O_CLOEXEC` into the openat flags in `neper_os_open`.

### [info] `run`/`nptest_spawn` truncate-overwrite capture files beside the output path
- **Location:** `src/main.e:1452-1504` (`run_program`), `1679-1694` (`nptest_spawn`)
- **Category:** overwrite semantics
- **Description:** stdout/stderr are captured by opening `<path>.stdout`/`.stderr`
  (and `.out`/`.err` for tests) with `truncate: true`, overwriting any pre-existing
  file with that suffix.
- **Recommendation:** document the overwrite semantics; optionally refuse when the
  capture path already exists.

### [info] `json_unescaped_after` encodes lone surrogates as invalid UTF-8
- **Location:** `src/main.e:4855-4863` (surrogate handling), `4884-4905` (`utf8_append`)
- **Category:** malformed-input handling
- **Description:** a `\uD800`-style escape not followed by a valid low surrogate

- **Recommendation:** replace unpaired surrogates with U+FFFD or reject the record.

## 8. Crypto (`lib/e/crypto/`, `algo/rand.e`, `bignum.e`, `ecc.e`, `privacy.e`, `hash.e`)

### [medium] Shamir coefficients drawn from a non-cryptographic PRNG
- **Location:** `lib/e/crypto/secret.e:72-81` (line 81: `u8(rand.pcg64_next(rng) & 255u64)`)
- **Category:** weak randomness
- **Description:** Shamir secret-sharing coefficients are drawn from `e.algo.rand`'s
  PCG64, which the module header itself flags as non-cryptographic. Predictable
  coefficients downgrade Shamir to ~1-share secrecy (an attacker who can recover
  the PRNG stream needs only one share).
- **Recommendation:** seed the coefficient generator from a CSPRNG (ChaCha20 DRBG)
  fed by OS entropy.

### [medium] Variable-time modular exponentiation
- **Location:** `lib/e/algo/bignum.e:620-683` (branches at 646, 671; `mont_mul` conditional subtract at 576)
- **Category:** side channel
- **Description:** `int_mod_pow` branches on exponent bits and does a conditional
  subtract in `mont_mul`, leaking secret exponents through timing. The crypto
  surfaces correctly avoid it (`kx.e:10-11`, `sign.e:889/1252`), but it remains a
  public unguarded primitive.
- **Recommendation:** make it constant-time (or clearly document it as
  non-secret-only and add a lint/contract that forbids secret exponents).

### [medium] PKCS#7 unpadding is a padding oracle
- **Location:** `lib/e/crypto/cipher.e:224-234` (early exit `if usize(data[i]) != pad { ret Invalid }` at 230)
- **Category:** padding oracle
- **Description:** unpadding compares byte-by-byte and returns early on mismatch.
  Combined with unauthenticated CBC, this is a classic padding oracle that recovers
  plaintext.
- **Recommendation:** make unpadding constant-time (compute validity over the whole
  block), and always pair block ciphers with an AEAD/MAC.

### [medium] ML-KEM decapsulation performs `%`/`/` on secret data (needs verification)
- **Location:** `lib/e/crypto/kx.e:443` (acknowledged), `487-489`, `632`, `786-790`
- **Category:** side channel
- **Description:** `kem_pke_decrypt` runs `% kem_q()` NTT and `/3329` compress over
  secret `s`/`w`; if the interpreter's division is data-dependent, this is
  variable-time on secret key material. Flagged "needs verification" against the
  actual backend.
- **Recommendation:** confirm constant-time division in the backend or use
  constant-time reduction for secret operands.

### [low] No OS-entropy CSPRNG in the crypto library
- **Location:** `lib/e/crypto/random.e:1-5`; `lib/e/algo/rand.e:1-3`
- **Category:** weak randomness
- **Description:** all randomness is deterministic caller-seeded ChaCha20 or
  non-crypto PCG64; there is no secure source for keys/nonces.
- **Recommendation:** add an OS-entropy-backed CSPRNG and make key/nonce APIs take
  it by default.

### [low] Differential-privacy noise drawn from a non-crypto PRNG
- **Location:** `lib/e/algo/privacy.e:5-7`, `25`, `64`, `73`
- **Category:** weak randomness
- **Description:** Laplace/Gaussian/exponential noise is drawn from PCG64, which is
  recoverable from output, weakening the DP guarantee.
- **Recommendation:** use a CSPRNG for DP noise.

### [low] Missing secret zeroization
- **Location:** `lib/e/crypto/secret.e:76`, `109`; `lib/e/crypto/kdf.e:8-9`
- **Category:** key handling
- **Description:** `terms`/`basis`/`shares` are never wiped, and KDF notes that
  nothing wipes caller buffers.
- **Recommendation:** zeroize intermediate secret buffers after use.

### [info] `equal_constant_time` early length return
- **Location:** `lib/e/crypto/hash.e:641-642`
- **Category:** side channel (latent)
- **Description:** returns on length mismatch; only used with fixed-size tags today.
- **Recommendation:** none urgent; note as a contract.

**Notes (crypto):** verified safe — masked AES S-box/GHASH/Poly1305, correct
HMAC/HKDF/PBKDF2/scrypt/bcrypt/Argon2id parameters, X25519 masked ladder, Ed25519
constant-time (only public exponents), ML-KEM implicit-rejection masked compare,

## 9. Network & OS boundary (`lib/e/net/`, `os.*`, `proc.e`, `db/`, `fs*`, `path.e`)

### [medium] TLS hostname verification silently skipped when `server_name` is empty
- **Location:** `lib/e/net/tls.e:641` (and `lib/e/crypto/x509.e:728`)
- **Category:** TLS certificate / hostname-validation gap
- **Description:** `verify_certificate_set` sets `options.dns_name = config.server_name`,
  and x509 `verify` only enforces the name when `options.dns_name.len > 0`.
  `fill_client_hello` only bounds `server_name.len > 253`, so a client constructed
  with `server_name: ""` sends no SNI and performs zero hostname validation — chain/
  signature/validity still run, so any CA-valid certificate for any name is accepted.
  Silent MITM if the caller omits `server_name`.
- **Recommendation:** for the client role, require a non-empty `server_name` (error)
  unless an explicit "skip verification" flag is set.

### [low] DoH response-body parser: `Content-Length` overflow; `Transfer-Encoding` ignored
- **Location:** `lib/e/net/dns.e:720-732`
- **Category:** HTTP parsing / integer overflow
- **Description:** `content_length = content_length * 10usize + usize(line[i] - 48u8)`
  accumulates with no overflow check, and chunked transfer-encoding is never handled
  (only Content-Length is trusted, without the CL+TE smuggling cross-checks
  `e.net.http` applies). In a memory-safe language this cannot corrupt memory, but a
  wrapped value mis-slices the body.
- **Recommendation:** bound the accumulation and explicitly reject or support
  chunked/CL+TE combinations.

### [low] DoH request builder writes `host`/`path` unvalidated (header injection)
- **Location:** `lib/e/net/dns.e:673-693`
- **Category:** HTTP header injection
- **Description:** `query_doh` copies `host` into the `Host:` header and `path` into
  the request line with no CR/LF/space validation, so a caller-supplied value can
  inject extra headers/request lines.
- **Recommendation:** validate `host`/`path` (no CR/LF/control bytes; `path` no
  spaces), mirroring `e.net.http.write_request`.

### [low] PKCE code verifier generated with a non-cryptographic PRNG
- **Location:** `lib/e/net/http/auth.e:38-46`
- **Category:** cryptographic randomness
- **Description:** `pkce_verifier` fills from `rand.pcg64_bounded(rng, 66u64)` (PCG64);
  RFC 7636 requires a high-entropy cryptographic verifier. A predictably seeded
  `Pcg64` makes the verifier/challenge guessable, defeating code-exchange protection.
- **Recommendation:** draw the verifier from a CSPRNG (e.g. `os.random`) or enforce a
  CSPRNG-seeded generator.

### [info] TLS `entropy` is caller-supplied and used directly as ECDHE key + nonce
- **Location:** `lib/e/net/tls.e:268-269`, `437-439`
- **Category:** key management
- **Description:** `config.entropy[32..64]` becomes the X25519 ephemeral secret and
  `[..32]` the Hello random; reuse/weak sourcing makes the ECDHE key static (no
  forward secrecy) and repeats the random, violating TLS 1.3 uniqueness.
- **Recommendation:** document `entropy` must be fresh/CSPRNG per connection, or
  generate the ephemeral key internally.

### [info] PATH-based tool lookup can be hijacked
- **Location:** `lib/e/os/shell.linux.e:117-137`
- **Category:** command/path resolution
- **Description:** `find_program` walks `PATH` and returns the first match;
  `open_uri`/`send_notice`/`credential_tool`/`power_inhibit` spawn it. A malicious
  earlier `PATH` entry plants a same-named `xdg-open`/`notify-send`/`secret-tool`/
  `systemd-inhibit`. (Spawning is argv/execve, not a shell.)
- **Recommendation:** prefer absolute trusted paths or sanitize `PATH` for privileged
  verbs like `secret-tool`.

### [info] DNS stub resolver uses plain UDP without DNSSEC (documented)
- **Location:** `lib/e/os.linux.e:1296-1306`, `2362-2371`
- **Category:** DNS integrity
- **Description:** the OS resolver uses 512-byte plain UDP DNS with no EDNS0/DNSSEC
  (the standalone `e.net.dns` has DNSSEC but isn't used here). Transaction ID is
  matched and the socket is connected — sound off-path — but plain-DNS
  on-path/poisoning exposure remains.
- **Recommendation:** acceptable for a stub resolver; use DoH/DNSSEC where high
  assurance is required.

**Notes (network/OS):** verified safe — no SQL/string-built queries (`db/query.e`
is a typed in-memory executor); no command injection (`proc.e`/`os.linux.e` spawn
via argv + execve, never a shell); the HTTP parser rejects CL+TE, duplicate/
conflicting Content-Length, obs-fold, and validates header values (no smuggling/
splitting); protocol parsers (coap/mqtt/stun/ws/quic/http3/dns/idna/glob) are
bounds-checked with no length-field overflow (MQTT remaining-length capped, QUIC
varint capped, DNS pointers must go backwards, glob uses a step budget); `idna.e`
implements IDNA 2008 with PVALID/CONTEXTJ/Bidi and rejects non-canonical punycode,
and x509 `dns_match` is strict ASCII (no homograph bypass in cert matching);
`fs`/`path` delegate symlink containment to `openat2 RESOLVE_BENEATH/NO_SYMLINKS`
and `NtCreateFile OBJ_DONT_REPARSE`.

## 10. Formats & text (`lib/e/fmt/`, `lib/e/text/`, `parse/`, `str.e`, `bytes.e`, `io.e`)

### [medium] msgpack `str`/`bin`/`ext` length prefixes allocate unbounded memory
- **Location:** `lib/e/fmt/msgpack.e:57` (`read_bytes`, called at 107, 115, 152, 177)
- **Category:** deserialization / memory-exhaustion DoS
- **Description:** `read_bytes` does `mem.alloc[u8](a, count)` with `count` from a
  1/2/4-byte length prefix and no cap. A `str32`/`bin32`/`ext32` header can request
  ~4 GiB. Arrays/maps cap at 16 MiB (`TooLarge`, lines 187/202), but strings/bin/ext
  do not — inconsistent and attacker-controlled.
- **Recommendation:** apply the same cap (or bound by remaining input) to
  str/bin/ext before allocating.

### [medium] CBOR tree `decode` allocates containers from an unbounded length prefix
- **Location:** `lib/e/fmt/cbor.e:612`, `623`, `635`
- **Category:** deserialization / memory-exhaustion DoS
- **Description:** `decode` takes the array/map argument directly as a count and
  allocates that many `Value`/`Pair` entries with no bound. `0x9a ff ff ff ff`
  (count 2^32−1) triggers an enormous allocation before the loop hits `Truncated`.
  The streaming `skip_depth` path is depth-capped (128) and safe; only the tree
  path is unbounded.
- **Recommendation:** reject counts over a configurable cap (or over `remaining`)
  before allocating, mirroring msgpack's `TooLarge`.

### [low] YAML `\u`/`\U`/`\x` escapes emit invalid UTF-8
- **Location:** `lib/e/fmt/yaml.e:221-236` (`unescape_double`) and `173-194` (`push_utf8`)
- **Category:** UTF-8 validation bypass
- **Description:** `push_utf8` encodes whatever scalar the escape yields with no
  check for `> 0x10FFFF` or surrogates; `\U0000D800`/`\U00110000` produce bytes
  `e.text.utf8` rejects. `lib/e/fmt/toml.e:116` and json.e handle this correctly.
- **Recommendation:** reject surrogates and `> 0x10FFFF` before `push_utf8`.

### [low] XML numeric character references accept surrogates
- **Location:** `lib/e/fmt/xml.e:166` (validation) and `93-114` (`push_scalar`)
- **Category:** UTF-8 validation bypass
- **Description:** `decode` checks only `scalar > 1114111u64 || scalar == 0u64`;
  `&#xD800;` passes and `push_scalar` writes `ED A0 80` (an encoded surrogate).
- **Recommendation:** also reject 0xD800–0xDFFF, as XML 1.0 requires.

### [low] tar base-256 size field integer overflow
- **Location:** `lib/e/fmt/tar.e:60-68`
- **Category:** integer overflow in entry-size computation
- **Description:** `value = (value << 8u32) | u64(field[at])` over up to 11 bytes
  shifts left up to 88 bits into a `u64`, silently discarding high bits; a wrapped
  size under-counts `remaining`/`bytes` and bypasses `byte_limit` (misparse only).
- **Recommendation:** overflow-check the accumulation or reject oversized base-256
  fields.

### [low] tar PAX `length`/`size` decimal parsing integer overflow
- **Location:** `lib/e/fmt/tar.e:141-152` (length), `170-181` (size)
- **Category:** integer overflow in entry-size computation
- **Description:** `length = length * 10usize + digit` and `size = size * 10u64 + digit`
  are unchecked; a ~20+-digit value wraps and misparses record boundaries, and a
  wrapped `size` defeats `byte_limit`.
- **Recommendation:** reject when `x > (max - digit)/10`.

### [low] zip `directory_offset + directory_size` can wrap u64; offsets cast to i64
- **Location:** `lib/e/fmt/zip.e:134`, `62`
- **Category:** integer overflow in entry-size computation
- **Description:** `directory_size` is capped at 64 MiB first, but
  `directory_offset + directory_size > size` can wrap and pass; the seek/read then
  fails closed and `i64(offset)` of a > i64::MAX value goes negative. Not
  memory-unsafe; boundary check is not overflow-safe. "needs verification" for
  impact beyond a failed parse.
- **Recommendation:** use `directory_offset > size || directory_size > size - directory_offset`.

### [info] `e.text.template` performs no output escaping
- **Location:** `lib/e/text/template.e:9` and `174-188` (`write_value`)
- **Category:** template injection (by design)
- **Description:** `.Text`/`.Bytes` are written verbatim; no code execution, but
  HTML rendering is XSS-prone. `e.fmt.html.template` is the intended escaping engine.
- **Recommendation:** route all HTML/markup output through `e.fmt.html.template`.

### [info] html/template URI scheme filter: non-alpha scheme bypasses the allowlist
- **Location:** `lib/e/fmt/html/template.e:241-253` (`write_uri_escaped`)
- **Category:** URL filtering (defense-in-depth)
- **Description:** a scheme is replaced with `#unsafe` only when all-ASCII-alpha and
  not http/https/mailto; a non-alpha scheme is not rejected. Percent-encoding
  neutralizes control/space bytes and `&`→`&amp;`, so no working `javascript:`
  vector was found — hardening gap, not an exploitable bypass.
- **Recommendation:** reject any scheme (after stripping C0 controls/spaces) that
  isn't known-good.

**Notes (formats):** verified safe — YAML anchors/aliases/tags/directives are
`Unsupported` (no billion-laughs), depth-bounded; XML DOCTYPE/external entities
`Unsupported` (XXE-safe); zip/tar path traversal blocked (`name_legal`/`name_allowed`
reject absolute/drive-letter/backslash/`..`); decompression codecs (zlib/zstd/gzip/
bzip2/lzma/lz4/snappy) are output-bounded; `e.text.regex` is a Pike VM with no
backtracking (ReDoS-safe); `e.text.utf8` strictly rejects overlong/surrogate/
`>U+10FFFF`; json.e enforces max_depth and duplicate-key detection; bson spans
checked against enclosing length.
